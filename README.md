# TGparserWords — парсер чатов Telegram по ключевым словам

Присылаете боту ссылки на чаты (хоть 50 сразу), задаёте ключевые слова — софт сам
проходит по всем чатам, собирает подходящие сообщения и отдаёт их списком и файлом CSV.
Дополнительно умеет мониторить новые сообщения в реальном времени.

## Как это устроено

Два компонента работают вместе в одном процессе:

| Компонент | Файл | Зачем |
|---|---|---|
| Бот-интерфейс (aiogram) | `bot.py` | кнопки и команды: чаты, слова, запуск поиска, выгрузка |
| Движок парсера (Telethon) | `parser.py` | читает историю чатов от вашего аккаунта и ищет совпадения |
| База (SQLite) | `storage.py` | чаты, слова, найденные сообщения, настройки |

**Почему нужен обычный аккаунт, а не только бот.** Бот по правилам Telegram не может
читать переписку в чатах, куда его не добавили администратором. Поэтому чтение истории
идёт через ваш личный аккаунт (Telethon, протокол MTProto), а бот — это только пульт
управления. Так работают все подобные парсеры.

## Установка

Нужен Python 3.10+.

```bash
git clone <репозиторий>
cd TGparserWords

python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

### 1. Получите ключи

1. **API_ID и API_HASH** — на https://my.telegram.org → *API development tools* → создать приложение.
2. **BOT_TOKEN** — напишите [@BotFather](https://t.me/BotFather), команда `/newbot`.
3. **Свой Telegram ID** — напишите [@userinfobot](https://t.me/userinfobot).

### 2. Заполните .env

```bash
cp .env.example .env
```

Откройте `.env` и впишите `API_ID`, `API_HASH`, `BOT_TOKEN`, `OWNER_IDS` (ваш ID —
без него бот пустит к парсеру кого угодно).

### 3. Авторизуйте аккаунт (один раз)

```bash
python login.py
```

Введите номер телефона, код из Telegram и пароль 2FA, если он включён. Рядом появится
файл `parser.session` — это ключ от вашего аккаунта, **никому его не передавайте**.

### 4. Запустите бота

```bash
python bot.py
```

Откройте своего бота в Telegram и нажмите `/start`.

### 5. Автозапуск после перезагрузки сервера (опционально)

Чтобы бот сам поднимался после перезагрузки и перезапускался при падении,
установите его как systemd-сервис (Linux-сервер с systemd):

```bash
sudo ./scripts/install_service.sh
```

Скрипт проверит, что venv и `.env`/`parser.session` уже на месте, подставит
реальные пути в `systemd/tgparserwords.service.template` и включит автозапуск.

```bash
systemctl status tgparserwords     # статус
journalctl -u tgparserwords -f     # логи в реальном времени
systemctl restart tgparserwords    # перезапуск после изменения .env
systemctl disable tgparserwords    # убрать из автозапуска
```

## Как пользоваться

1. **🔗 Чаты** → пришлите ссылки, каждая с новой строки. Понимаются все форматы:
   `https://t.me/chatname`, `@chatname`, `t.me/+AbCdEf`, `t.me/joinchat/...`,
   `https://t.me/c/1234567/89`, а также ссылки на конкретные сообщения.
2. **🔑 Ключевые слова** → пришлите слова или фразы через запятую либо с новой строки.
3. **🚀 Запустить поиск** → бот пройдёт по всем чатам и покажет прогресс. Дубли сообщений
   между запусками не повторяются — база помнит, что уже находила.
4. **📤 Экспорт CSV** → файл со столбцами: дата, чат, автор, ключевое слово, текст, ссылка
   (открывается в Excel без проблем с кириллицей).
5. **📡 Мониторинг** → новые сообщения с ключевыми словами прилетают в бот сразу.
   Чат должен быть распознан хотя бы одним поиском.

### Команды

```
/chats /delchat N /clearchats     — список чатов и управление им
/words /delword слово /clearwords — ключевые слова
/search                           — запустить поиск
/results                          — последние находки
/export                           — выгрузка CSV
/clearresults                     — очистить базу находок
/monitor on|off                   — мониторинг новых сообщений
/settings  /set ключ значение     — параметры поиска
```

### Параметры поиска (`/settings`)

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `days` | 30 | за сколько дней искать; `0` — без ограничения по дате |
| `limit` | 500 | максимум сообщений на чат за прогон |
| `mode` | `smart` | `smart` — слово с любым окончанием («аренда» → «аренду», «аренде»);<br>`exact` — только точная форма;<br>`substring` — любое вхождение («ренд» → «субаренда») |
| `scan` | `off` | `off` — быстрый поиск силами Telegram;<br>`on` — полное сканирование истории (медленнее, но не зависит от индексации) |

Пример: `/set days 90`, `/set mode exact`, `/set scan on`.

## Важные ограничения

- **Приватные чаты.** Читать можно только то, что доступно вашему аккаунту. Публичные
  каналы и группы читаются свободно; в приватные нужно вступить — вручную либо поставив
  `AUTO_JOIN=true` в `.env` (тогда аккаунт сам вступает по ссылке-приглашению).
- **Лимиты Telegram.** При частых запросах приходит FloodWait — парсер ждёт паузу
  автоматически (до `MAX_FLOOD_WAIT` секунд, дальше пропускает чат). Не ставьте
  `REQUEST_DELAY` меньше 0.5 и не гоняйте поиск по 50 чатам каждые пять минут:
  за агрессивный парсинг аккаунты блокируют. Для работы лучше завести отдельный номер.
- **Ключевые слова** ищутся по тексту сообщений и подписям к медиа; текст внутри
  картинок и файлов не распознаётся.

## Тесты

```bash
python -m unittest discover -s tests
```

Проверяются разбор ссылок, сопоставление ключевых слов, работа базы и поиск на
подставном клиенте — без обращения к Telegram.

## Структура

```
bot.py        интерфейс бота: кнопки, команды, отчёты
parser.py     Telethon-клиент: ссылки, поиск, мониторинг
storage.py    SQLite: чаты, слова, находки, настройки
config.py     чтение .env
login.py      разовая авторизация аккаунта
tests/        тесты
scripts/      установка автозапуска (systemd)
systemd/      шаблон systemd-юнита
```
