# TGparserWords — парсер чатов Telegram по ключевым словам

Присылаете боту ссылки на чаты (хоть 50 сразу), задаёте ключевые слова — софт сам
проходит по всем чатам, собирает подходящие сообщения и отдаёт их списком и файлом CSV.
Дополнительно умеет мониторить новые сообщения в реальном времени.

## Как это устроено

Два компонента работают вместе в одном процессе:

| Компонент | Файл | Зачем |
|---|---|---|
| Бот-интерфейс (aiogram) | `bot.py` | кнопки и команды: чаты, слова, запуск поиска, выгрузка |
| Движок парсера (Telethon) | `parser.py` | читает историю чатов от вашего аккаунта и ищет совпадения |
| База (SQLite) | `storage.py` | чаты, слова, найденные сообщения, настройки |

**Почему нужен обычный аккаунт, а не только бот.** Бот по правилам Telegram не может
читать переписку в чатах, куда его не добавили администратором. Поэтому чтение истории
идёт через ваш личный аккаунт (Telethon, протокол MTProto), а бот — это только пульт
управления. Так работают все подобные парсеры.

## Установка

Нужен Python 3.10+.

```bash
git clone <репозиторий>
cd TGparserWords

python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

### 1. Получите ключи

1. **API_ID и API_HASH** — на https://my.telegram.org → *API development tools* → создать приложение.
2. **BOT_TOKEN** — напишите [@BotFather](https://t.me/BotFather), команда `/newbot`.
3. **Свой Telegram ID** — напишите [@userinfobot](https://t.me/userinfobot).

### 2. Заполните .env

```bash
cp .env.example .env
```

Откройте `.env` и впишите `API_ID`, `API_HASH`, `BOT_TOKEN`, `OWNER_IDS` (ваш ID —
без него бот пустит к парсеру кого угодно).

### 3. Авторизуйте аккаунт (один раз)

```bash
python login.py
```

Введите номер телефона, код из Telegram и пароль 2FA, если он включён. Рядом появится
файл `parser.session` — это ключ от вашего аккаунта, **никому его не передавайте**.

### 4. Запустите бота

```bash
python bot.py
```

Откройте своего бота в Telegram и нажмите `/start`.

### 5. Автозапуск после перезагрузки сервера (опционально)

Чтобы бот сам поднимался после перезагрузки и перезапускался при падении,
установите его как systemd-сервис (Linux-сервер с systemd):

```bash
sudo ./scripts/install_service.sh
```

Скрипт проверит, что venv и `.env`/`parser.session` уже на месте, подставит
реальные пути в `systemd/tgparserwords.service.template` и включит автозапуск.

```bash
systemctl status tgparserwords     # статус
journalctl -u tgparserwords -f     # логи в реальном времени
systemctl restart tgparserwords    # перезапуск после изменения .env
systemctl disable tgparserwords    # убрать из автозапуска
```

## Как пользоваться

1. **🔗 Чаты** → пришлите ссылки, каждая с новой строки. Понимаются все форматы:
   `https://t.me/chatname`, `@chatname`, `t.me/+AbCdEf`, `t.me/joinchat/...`,
   `https://t.me/c/1234567/89`, а также ссылки на конкретные сообщения.
2. **🔑 Ключевые слова** → пришлите слова или фразы через запятую либо с новой строки.
3. **🚀 Запустить поиск** → бот пройдёт по всем чатам и покажет прогресс. Дубли сообщений
   между запусками не повторяются — база помнит, что уже находила.
4. **📤 Экспорт CSV** → файл со столбцами: дата, чат, автор, ключевое слово, текст, ссылка
   (открывается в Excel без проблем с кириллицей).
5. **📡 Мониторинг** → новые сообщения с ключевыми словами прилетают в бот сразу.
   Чат должен быть распознан хотя бы одним поиском.
6. **🗂 История (JSON)** → пришлите ссылку на один публичный канал/чат — бот выгрузит всю
   доступную историю (без фильтра по ключевым словам) JSON-файлом: дата и время, текст,
   ссылки из сообщения, ID сообщений, ссылка на сообщение и метаданные вложений (тип, имя
   файла, mime, размер), если есть. Файл пишется на диск по мере получения сообщений —
   размер чата не ограничен оперативной памятью бота.
7. **🖼 История (HTML+медиа)** → то же самое, но собирает читаемую HTML-страницу с
   реальными картинками, видео и аудио — вложения **встроены прямо в файл** (как data:URI),
   без отдельной папки с медиа. Так надёжнее: у некоторых браузеров при открытии локального
   HTML-файла (`file://`) не работают относительные ссылки на соседние файлы, из-за чего
   картинки могли не отображаться, даже если реально были скачаны. Открывается одним файлом
   в браузере, ничего распаковывать не нужно. Файлы крупнее 20 МБ не встраиваются — вместо
   них в странице остаётся ссылка на оригинальное сообщение в Telegram.

   Для обоих вариантов: чем больше канал, тем дольше идёт выгрузка (для HTML — особенно,
   из-за скачивания медиа). Статус в чате обновляется по ходу дела (не реже раза в ~8
   секунд), так что «зависший» на вид процесс обычно просто медленно качает вложения —
   если нужно прервать его, не дожидаясь, есть команда **/cancel**.

   **Лимит Telegram на документы у ботов (~50 МБ) обходится автоматически**: если выгрузка
   не помещается в один файл, бот сам режет её на несколько (`история.part001of003.json` /
   `.html`) и присылает по очереди. Каждая часть — самостоятельный, независимо открываемый
   файл (для HTML — со своими встроенными вложениями, ничего дополнительно соединять не
   нужно). Порог настраивается через `MAX_UPLOAD_MB` в `.env` (по умолчанию 45 МБ — с запасом
   ниже лимита Telegram).

### Команды

```
/chats /delchat N /clearchats     — список чатов и управление им
/words /delword слово /clearwords — ключевые слова
/search                           — запустить поиск
/results                          — последние находки
/export                           — выгрузка CSV
/clearresults                     — очистить базу находок
/monitor on|off                   — мониторинг новых сообщений
/exporthistory                    — выгрузка полной истории чата в JSON
/exporthistoryhtml                — выгрузка полной истории чата в HTML (медиа встроены)
/cancel                           — прервать текущий поиск или выгрузку
/settings  /set ключ значение     — параметры поиска
```

### Параметры поиска (`/settings`)

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `days` | 30 | за сколько дней искать; `0` — без ограничения по дате |
| `limit` | 500 | максимум сообщений на чат за прогон |
| `mode` | `smart` | `smart` — слово с любым окончанием («аренда» → «аренду», «аренде»);<br>`exact` — только точная форма;<br>`substring` — любое вхождение («ренд» → «субаренда») |
| `scan` | `off` | `off` — быстрый поиск силами Telegram;<br>`on` — полное сканирование истории (медленнее, но не зависит от индексации) |

Пример: `/set days 90`, `/set mode exact`, `/set scan on`.

## Важные ограничения

- **Приватные чаты.** Читать можно только то, что доступно вашему аккаунту. Публичные
  каналы и группы читаются свободно; в приватные нужно вступить — вручную либо поставив
  `AUTO_JOIN=true` в `.env` (тогда аккаунт сам вступает по ссылке-приглашению).
- **Лимиты Telegram.** При частых запросах приходит FloodWait — парсер ждёт паузу
  автоматически (до `MAX_FLOOD_WAIT` секунд, дальше пропускает чат). Не ставьте
  `REQUEST_DELAY` меньше 0.5 и не гоняйте поиск по 50 чатам каждые пять минут:
  за агрессивный парсинг аккаунты блокируют. Для работы лучше завести отдельный номер.
- **Ключевые слова** ищутся по тексту сообщений и подписям к медиа; текст внутри
  картинок и файлов не распознаётся.

## Диагностика проблем

### `TelegramUnauthorizedError: Unauthorized`

Значит Telegram не принимает `BOT_TOKEN` — сам бот, не аккаунт (если Telethon в логах
пишет «авторизован как @...», значит с аккаунтом всё в порядке, дело только в токене).

1. **Проверьте токен напрямую, в обход бота и Python** — так сразу видно, дело в токене
   или в чём-то ещё:
   ```bash
   TOKEN=$(grep -m1 '^BOT_TOKEN=' .env | cut -d'=' -f2- | tr -d '[:space:]')
   curl -s "https://api.telegram.org/bot${TOKEN}/getMe"
   ```
   `{"ok":true,...}` — токен рабочий. `{"ok":false,"error_code":401,...}` — токен
   в `.env` реально битый или отозванный.
2. **Получите токен заново** через [@BotFather](https://t.me/BotFather) → `/mybots` →
   бот → **API Token**. Копируйте с телефона **долгим тапом → Copy** (целиком), а не
   ручным выделением текста — так часто теряются или добавляются символы.
3. **Нет ли той же переменной, уже экспортированной в окружении?**
   ```bash
   env | grep BOT_TOKEN
   ```
   Если что-то выводится — правки `.env` могли игнорироваться, старое значение
   перебивало новое. Найдите источник (`~/.bashrc`, `~/.profile`, systemd `Environment=`)
   и уберите, либо выполните `unset BOT_TOKEN` перед запуском.
4. После любой правки `.env` — обязательно перезапустите процесс
   (`systemctl restart tgparserwords`, если бот запущен вручную — перезапустите его).

### `Command 'python' not found`

На современных Linux используйте `python3` и `pip3`, либо ставьте `python-is-python3`.
Внутри активированного `venv` (`source .venv/bin/activate`) команда `python` работает
как обычно.

### `error: externally-managed-environment` при `pip install`

Debian/Ubuntu запрещают ставить пакеты в системный Python напрямую (PEP 668). Решение —
venv, а не обход защиты:
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### Ошибка при создании приложения на my.telegram.org

- **Short name** обязан быть латиницей и цифрами, 5-32 символа, без пробелов
  (кириллица или короткое имя вызывают ошибку сохранения формы).
- Форма нестабильно работает в мобильных браузерах — попробуйте версию для ПК
  (в Chrome: `⋮` → *Desktop site*) или зайдите с компьютера.
- Иногда форму блокирует VPN/прокси — попробуйте другую сеть (Wi-Fi ↔ мобильный интернет).

## Тесты

```bash
python -m unittest discover -s tests
```

Проверяются разбор ссылок, сопоставление ключевых слов, работа базы, поиск и выгрузка
истории (JSON/HTML) на подставном клиенте — без обращения к Telegram.

## Структура

```
bot.py        интерфейс бота: кнопки, команды, отчёты
parser.py     Telethon-клиент: ссылки, поиск, мониторинг, скачивание медиа
export.py     потоковая выгрузка истории чата: JSON и HTML со встроенными вложениями
storage.py    SQLite: чаты, слова, находки, настройки
config.py     чтение .env
login.py      разовая авторизация аккаунта
tests/        тесты
scripts/      установка автозапуска (systemd)
systemd/      шаблон systemd-юнита
```
